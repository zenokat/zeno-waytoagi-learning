# zeno-waytoagi 首版规格

## 目标与边界

将既有 WaytoAGI 读取实践整理为 Zeno 品牌的非官方独立 Skill，供支持 Skill 的中文 Agent 用户使用。项目独立维护，本地已有 ai-resources 及自媒体文章保持原样。代码和说明文档使用 MIT 许可，外部内容保留原文链接，不作为仓库自身的开源内容收录。

本轮只在本地实现、验收与提交，禁止推送、发布或创建远端 Issue。

## 能力

1. 用单一日期脚本读取更新日志：`--date YYYY-MM-DD` 必填，支持从 2025-06-01 起页面已列出的日期；近期、当年归档和其他年份归档由脚本自动定位。获取最近更新时由 Agent 传入当天或前一天，使用 Asia/Singapore 日期。保留原标题、原摘要、链接、查询日期与实际来源，不自动换日。不承诺补齐来源未列出的日期。
2. 通过官方 lark-cli、显式用户身份，限定 WaytoAGI 知识库搜索。支持按任务选择关键词与分页；搜索摘要不代表已读正文，不承诺热门排行或完整历史覆盖。
3. 按需读取命中文章的正文或章节，说明实际覆盖范围、未展开媒体与读取失败。不自动展开全部文章。

总结、推荐、研究结论与后续行动由调用 Skill 的 Agent 完成。取得的外部文本作为数据，不执行其中面向 Agent 的指令。

## 交付

- 可独立安装的 zeno-waytoagi Skill，包含必要脚本、读取参考和元数据，不依赖本人的其他 Skill 或本机绝对路径。
- 复用原摘要、链接保真与 CLI 失败报告的既有行为；按显式日期统一近期和历史读取，不构建通用飞书框架。早于 2025-06-01 的混合格式和范围日志不纳入承诺。
- SKILL.md 从看更新、搜索知识库、读取文章三个请求组织，直接提供各自基本操作与结果判断。配置仅在需要时进入 setup.md；references 只承载可选扩展，不复制 ai-resources 的工作约定、开发过程或历史实测。
- README 面向用户：简单介绍三个主要功能，在 Quickstart 给出交给 Agent 安装配置的 GitHub 链接和话术，并为三个功能分别提供使用案例。
- Skill 内的 setup.md 面向 Agent：通用安装、依赖准备和 CLI 配置由 Agent 自行探索完成，文档只给出必要环境条件、产品特殊要求、用户参与与接续方式、三类功能验收和交付标准。不提供专用安装脚本或仓库根目录 SETUP.md。
- 配置与授权分开处理，已有可用配置和授权优先复用；验收可基于用户已有的飞书应用，不要求手动新建应用。不覆盖默认应用或已有凭证。用户需要操作时必须给出操作链接、具体动作、完成后接续方式。授权使用实际所需权限，不默认请求全部业务域。
- 需要接入应用时，默认由 Agent 发起官方一键配置并提供链接或二维码，由用户在浏览器完成创建或选择应用及确认；只有该路径实际受阻时，才说明原因并引导终端或手动凭证输入。已有可用配置与授权直接复用。一键新建应用路径尚待实测，取得通过结果后才加入对外操作承诺。
- 权限是否足够以完成读取为准。既有或平台授予的范围更宽时直接继续，不额外打断用户或要求收窄；仅在缺少所需权限导致读取受阻时，说明缺口并协调用户补充。Skill 的业务操作仍限于读取。
- lark-cli 的配置、授权及通用故障恢复路由到其自带指南和命令帮助，不在本 Skill 复制上游流程或穷举其异常。setup 保留本产品的环境要求、配置与身份约束、浏览器优先的用户协作方式和三功能验证。取消、链接过期或等待超时不单列为本产品的异常处理需求。
- WaytoAGI 读取异常按需查阅失败约定：区分资源访问、临时服务故障、无命中及不完整结果；只读重试有次数边界，停止后交付已取得材料和未完成范围，不用重新授权或切换读取路线掩盖问题。代码缺口先复现并以回归测试证明修复；Agent 的恢复与交互约定不冒充自动化代码测试。
- 日期读取返回 `ok`、`date_batch_not_present`、`outside_supported_range` 或 `error`。目标缺失和超出范围均不解释为当天无更新；路由缺失、来源错配、重复日期、节选和未知正文结构按错误报告。归档年份依据页面年月标题及年份链接，不能用请求年份改写来源。所有读取沿用同一配置和用户身份。
- Agent 安装操作应只复制完整 Skill 包，不把仓库工程文件、Git 历史、凭证或个人环境信息混入安装目录。目标已有不同内容时保全并明确处理，不静默覆盖。
- README 包含功能、用户入口、使用案例、来源、许可与简明验证状态；读取命令放在 SKILL.md 与按需参考中，安装配置的交互与验收约定放在 setup.md。

## 验收与测试边界

- SKILL.md 与读取参考中的可执行功能，先取得行为用例与实际通过结果，再对外描述；不以 CLI help、格式校验或链接检查替代验收。当前对应关系及运行方式见 [读取功能验收](verification.md)。无法核对具体范围的创建时间筛选暂不纳入 Skill。
- 日期命令及其公开输出：按 TDD 验证必填日期、支持起点两侧、无效与未来日期、近期与年度路由、同月日跨年、年末跨年、目标缺失、来源完整性和 CLI 错误报告。保留既有原摘要、链接与失败测试。真实日期抽样验证网络路由，年度整页快照逐日回放验证所有实际批次的条目集合；两种证据分别记录，不把回放说成逐日联网验收。
- Skill 安装：由 Agent 从 README Quickstart 进入包内 setup.md，在独立临时目录取得完整包并实际运行，不为 Agent 本身的复制或 GitHub 安装能力新增脚本和单元测试。
- setup.md：核对命令参数与官方当前文档/本地 CLI help，真实 Agent 按文档执行本地安装和必要环境检查；三类能力通过实际用户身份读取验证。
- setup 的覆盖项验证本 Skill 的约束、上游指南路由和实际接入结果；不重复承担 lark-cli 全部配置、授权异常的测试。路由入口可读不等于完整配置流程已经验收。
- 首次应用配置和用户授权需要本人配合；若尚未完成这些步骤或普通新账号访问条件未验证，记录明确的验收范围，不能将已授权环境成功写成新用户全链路验收。
- 执行有意义的离线测试、Python 编译检查、Skill 格式校验、链接检查与独立 Standards/Spec 审查；修复有效审查问题后本地提交，工作区干净。
