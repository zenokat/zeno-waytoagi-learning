# Agent 行为测试

[test_waytoagi_agent.py](../tests/test_waytoagi_agent.py) 运行真实 Codex，让它读取当前 Skill、执行用户任务，再检查公开 CLI 调用、安装产物与最终答复。输入不提供预期答案；不以文档是否包含某句话判定通过。

## 测试边界

- 合成场景只替换外部 `lark-cli`，不替换 Skill 内的日期脚本或定位函数。原始记录留在临时目录，报告仅保存合成交付、调用及无正文的检查摘要。
- `lark-cli skills read` 的指南从本次 CLI 实际读取后缓存，避免自行编造一套上游授权步骤。替身只模拟相应外部响应，不证明上游实现。
- 安装目标包含 Skill 名称，冲突场景将用户修改直接放在该目标内；以完整文件内容对照判断保全，而非只看答复声称保留。
- 分页断言检查实际令牌、查询条件、次数、等待时间与保留的链接；章节断言检查目录刷新和实际块 ID；最终交付检查语义可观察结果，允许“返回0条”等等价说法。
- 权限、资源和格式错误来自外部响应；检查 Agent 是否停止或交还用户，以及是否清理敏感字段。恶意文本场景还检查其要求创建的文件没有出现。
- 真实 setup 用例另需显式开启，只复用已有授权。其 CLI 白名单仅允许读取和诊断，阻止配置写入、登录或权限修改；用真实返回的成功状态、条数、正文长度和链接核对，正文不写入报告。

每次是一个真实 Agent 的行为样本，不证明任何模型、提示词或账号都会永远遵从这些约定。真实服务兼容性由 [联网测试](../tests/test_waytoagi_live.py) 补充；上游首次授权的历史真实证据见 [setup-walkthrough.md](setup-walkthrough.md)，合成浏览器交接不能替代它。

## 重复运行

使用已独立登录 Codex、安装好官方 CLI 的专用测试容器。本次环境为 `zeno-waytoagi-setup-20261013-01`，非特权、没有宿主目录挂载，用户为 `setup-agent`。

```bash
python3 tests/run_agent_tests.py \
  --container zeno-waytoagi-setup-20261013-01 \
  --report /tmp/waytoagi-agent-results.json
```

需要网络代理时，为这条测试命令设置现有代理环境变量；不修改系统代理。测试驱动只将这些变量传入容器。加入 `--case pagination` 可筛选场景；可重复传入 `--case`。完整真实已授权 setup 另加 `--live-setup`，单独运行可同时指定 `--case current_setup_with_real`。

驱动临时保全容器两个 CLI 符号链接，替换成测试隔离入口，并在结束时恢复。没有活跃场景的业务调用会被阻断；这避免登录 Shell 重置 PATH 后误用真实 CLI。原链接发生外部变化时停止恢复并保留备份，不覆盖其他修改。

该 Debian 容器不支持被测 Codex 内部的 bwrap 命名空间，因此由专用 Docker 容器提供隔离。驱动拒绝特权或带挂载容器；测试代码也拒绝在 Docker 之外使用内部无沙箱模式。不复制宿主凭证，不要求用户重新授权。此运行器不属于安装包。

默认 `python3 -m unittest discover -s tests` 跳过 Agent 和联网测试。显式选择的测试执行失败必须报告失败，不能以跳过补成通过。CLI 路由、模型服务或测试隔离环境失败要先修正测试条件；只有实际产品行为不符需求时才修改产品。
